# Plano: Atualização das Specs vs Código Implementado

## Contexto

O projeto WhatsAppAI-000-platform tem **todo o código das 8 fases implementado**, mas as specs (`tasks.md`, `spec.md`, `plan.md`, `constitution.md`, `AGENTS.md`, `data-model.md`, `quickstart.md`) estão desatualizadas — refletem o estado do projeto antes da implementação completa. Além disso, existe uma **divergência crítica de stack**: as specs mencionam PostgreSQL 18, mas o código usa MySQL 8.4 LTS (decisão do ADR-0006).

---

### 1.1. Banco de Dados (CRITICAL)

| Documento | Diz | Código faz |
|---|---|---|
| `constitution.md` L28 | "PostgreSQL como infraestrutura central" | MySQL 8.4 LTS |
| `AGENTS.md` L29 | "Persistência: PostgreSQL 18" | MySQL 8.4 LTS |

| `tasks.md` T003 | "Configurar PostgreSQL 18" | MySQL 8.4 LTS |

### 1.4. Gaps Reais de Implementação

| Gap | Detalhe |
|---|---|
| Dockerfiles ausentes | `compose.yaml` referencia Dockerfiles que não existem |
| CI usa PostgreSQL | `.github/workflows/ci.yml` sobe PostgreSQL 18, mas código é MySQL |
| Test coverage baixo | ~16 métodos de teste; 16 integration tests falhando |
| Debug code pendente | `ObservabilityExtensions.cs`, `Program.cs`, `AdminTenantEndpoints.cs` |
| BotConfiguration não integrado ao worker | `AiOrchestrationWorker` não verifica `BotConfiguration.Mode` |
| Sem serviço de e-mail | Convites geram links mas não há delivery |
| Sem template messages | 24h window bloqueia mas sem implementação de templates |
