# Skill: criar testes

1. Derive cenários dos critérios de aceite, regras críticas e riscos do domínio.
2. Use unit tests para regras puras, integração para persistência e contratos, e frontend ou E2E para jornadas críticas.
3. Inclua falha, idempotência, concorrência e isolamento por tenant quando relevantes.
4. Evite testes que apenas espelhem a implementação sem verificar comportamento observável.

Fonte: [estratégia de testes](../regras/testes.md).
